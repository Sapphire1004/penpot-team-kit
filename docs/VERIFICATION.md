# 다중 사용자 검증

2026-11-15, macOS Docker 환경에서 이 저장소의 Compose를 새 `database`·`assets` 볼륨으로 실행했다. 기존 개인 Penpot 볼륨은 사용하지 않았다. Penpot 2.18.5·PostgreSQL 15·Valkey 8.1 구성이다.

| 항목 | 결과 |
| --- | --- |
| 별도 비밀번호 계정 로그인 | 임시 계정 11개 성공 |
| 같은 파일 동시 읽기 | 10세션 성공 |
| 실시간 협업 연결 | 서로 다른 계정의 WebSocket 10개 유지 |
| 동시 편집 | 8명이 각자 도형 수정 × 5회, 총 40회 저장·다른 참가자 전달 확인 |
| 뷰어 2명 | 변경 수신 성공, 쓰기 거부 |
| 팀 외부·다른 개인 프로젝트·미인증 접근 | 모두 거부 |
| 로그아웃 | 기존 세션 접근 거부 |
| MCP | initialize·4개 도구 조회 성공, 키 없는 디자인 실행 거부 |
| 정리 | 임시 계정 11개 삭제 요청, 재로그인 모두 거부 |

11개 검사를 통과했다. 동일 호스트 내부 Docker 네트워크에서 라운드별 8개 쓰기 완료는 39–92ms, 전체 동료 알림은 40–92ms였다. 이것은 짧은 실행의 관측값이며 인터넷 지연·LLM 응답 시간·브라우저 렌더 시간을 포함하지 않는다. [정리된 실제 결과 JSON](evidence/multiuser-2026-11-15.json)에 범위를 함께 기록했다.

초기 2026-11-13 시험은 협업·권한 검사 10개를 통과한 뒤 테스트 코드가 로그아웃에 필요한 `profile-id`를 보내지 않아 실패했다. 해당 호출을 수정하고 새 스택에서 위 전체 시험을 통과했다. 제품 로그아웃 결함으로 판단하지 않았다.

## 재현

```sh
./penpot up
./penpot test
```

호스트 Node 의존성 없이 일시적 Node 컨테이너로 실행한다. 임시 계정·팀·파일을 생성하고 finally에서 소켓과 계정을 정리한다. 프로필의 실제 DB 삭제는 Penpot의 지연 GC를 따르며 로그인 차단을 즉시 확인한다. 운영 디자인을 변경하지 않는다. 실행 결과는 `test-results/`에, 중단 시 정리용 비밀번호는 무시되는 `.local/`에 보관하고 정리 성공 시 제거한다.

예기치 않게 종료되었다면 `./penpot test:cleanup`을 실행한다. 테스트 전용 계정만 다루며 사용자의 기존 계정을 삭제하지 않는다.

## 아직 확인하지 않은 범위

브라우저 10개를 이용한 편집 UI·시각·장시간 부하, 서로 다른 네트워크 접속, 충돌하는 동일 속성 수정의 UX, 10명 동시 MCP 디자인 실행, 서버 최소 RAM·최대 사용자 수는 측정하지 않았다. 이 시험만으로 10인 운영 성능을 보증하지 않는다. 별도 기존 MCP 실험에서는 단순 화면 생성·속성 수정·읽기·PNG 내보내기를 확인했지만 그 개인 파일·키·증거 원본은 이 공개 키트에 포함하지 않는다.
